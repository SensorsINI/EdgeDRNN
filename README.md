# EdgeDRNN

EdgeDRNN contains a native PyTorch implementation of DeltaGRU training, the
SystemVerilog accelerator, portable RTL verification, and MiniZed bare-metal
software. The default configuration trains a small two-layer, 16-hidden-unit
network so the complete software-to-RTL flow can run quickly.

## Repository layout

```text
.
├── hdl/                         # Synthesizable SystemVerilog RTL
├── docs/                        # Architecture and RTL reading guides
├── python/
│   ├── edgedrnn/                # Native PyTorch package
│   │   ├── layers/              # DeltaGRU and recurrent layers
│   │   ├── datasets/            # Dataset plugins and CPS assets
│   │   ├── checkpoint.py        # Safe, versioned native checkpoints
│   │   ├── config.py            # CLI and experiment configuration
│   │   ├── exporter.py          # SDK, LUT, and RTL-vector export
│   │   ├── model.py             # torch.nn model
│   │   └── trainer.py           # Explicit train/validate/test loops
│   ├── main.py                  # Compatibility CLI entry point
│   └── sdk/                     # Generated embedded-software assets
├── verification/rtl/
│   ├── tb/                      # Simulator-independent testbench
│   ├── stimuli/                 # Generated vectors and manifests
│   └── scripts/                 # xsim and Verilator entry points
├── vivado/                      # MiniZed board and SDK sources
├── Makefile                     # Top-level workflow shortcuts
└── pyproject.toml               # Python package and dependencies
```

Generated checkpoints and metrics are written under `artifacts/` and are not
tracked. Simulator build products are isolated under `verification/rtl/build/`.

## Python setup

Python 3.10 or newer is required. PyTorch Lightning is not used. The package
depends directly on current PyTorch 2.x APIs and requests `torch>=2.6,<3`; a new
environment therefore installs the latest compatible native PyTorch release.
For CUDA-specific wheels, install PyTorch with the command generated by the
[official PyTorch selector](https://pytorch.org/get-started/locally/) before the
editable install.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
```

## Train and export

Run pretraining, DeltaGRU retraining, and hardware export in one command:

```bash
python python/main.py --step pretrain --run-through --device auto
```

The installed command-line entry point is equivalent:

```bash
edgedrnn --step pretrain --run-through --device auto
```

Individual stages can also be run independently:

```bash
python python/main.py --step pretrain
python python/main.py --step retrain
python python/main.py --step export
```

Training writes `best.pt`, `last.pt`, and `metrics.csv` under `artifacts/`.
Checkpoints contain native state dictionaries and optimizer/scheduler state;
loading uses PyTorch's restricted `weights_only=True` path. Export preserves the
existing packed hexadecimal and SDK C interfaces while writing RTL files to
`verification/rtl/stimuli/`. The generated `manifest.json` and
`edgedrnn_tb_config.svh` keep fixed-size simulator memories synchronized with
the selected model.

Use `python python/main.py --help` for model, quantization, dataset, path, and
device options. Legacy underscore-style argument names and `--accelerator gpu`
remain accepted.

## RTL verification

The same fixed-size SystemVerilog testbench supports both AMD xsim and
Verilator. It checks every response, fails with a nonzero status on a mismatch
or timeout, and emits `RTL_TEST_PASS` only after all golden outputs match.
It also inserts deterministic stream backpressure, checks every output TLAST,
and runs portable AXI4-Stream stability assertions. For a beginner-oriented
paper-to-code explanation, see
[`docs/rtl_design_walkthrough.md`](docs/rtl_design_walkthrough.md).

Run both simulators:

```bash
make rtl
```

Run one simulator:

```bash
make rtl-lint
make rtl-xsim
make rtl-verilator
```

The xsim script uses tools on `PATH`, then falls back to
`/opt/Xilinx/2026.1/Vivado`. Override that fallback when needed:

```bash
VIVADO_HOME=/tools/Xilinx/Vivado/2025.2 make rtl-xsim
```

`VERILATOR`, `VERILATOR_JOBS`, `STIMULI_DIR`, and `BUILD_ROOT` can also be
overridden. This makes
it possible to verify a temporary export without changing tracked vectors:

```bash
STIMULI_DIR=/tmp/export/stimuli \
BUILD_ROOT=/tmp/export/rtl-build \
./verification/rtl/scripts/run_verilator.sh
```

The complete default pipeline is available as:

```bash
make pipeline
```

## MiniZed hardware

- Download and extract the example Vivado project under `vivado/`.
- Install the MiniZed board files for the Vivado version in use.
- Copy updated synthesizable sources from `hdl/` into legacy embedded Vivado
  projects that do not reference this repository directly. Compile
  `edgedrnn_pkg.sv` before modules that import it; the verification file list in
  `verification/rtl/scripts/common.sh` shows the supported source order.
- Do not define `SIM_DEBUG` for synthesis. The verification scripts define it
  on the simulator command line, so `hdl/hdr_macros.v` remains synthesis-safe.
- The bare-metal driver and generated parameter/test headers are under
  `vivado/sdk/` and `python/sdk/`.
